## 2. 区画ごとの部品

### 上部と「目安です」
| 部品 | 仕様 |
|---|---|
| 題 | 「日陰MAP 新宿」（h1）。前の版の「新宿 地下・屋根ルート比較」から戻した。限界は下の帯で必ず伝える |
| 説明 | 「地下や屋根の下を通って、日なたを歩く時間をへらす道をさがします。」 |
| 目安です | 「**目安です。**地下・屋根のある道を公式の地図から手で拾いました。建物の影・季節・時刻は計算していません。」＋「くわしく」（データについてへ移動） |

### ① どこからどこへ？
| 部品 | 仕様 |
|---|---|
| 出発・到着 | 選ぶ欄（高さ 52px、文字 1.05rem）。5か所。見出しの前に「出」「着」の丸印（地図の印と同じ） |
| 入れかえ | 丸いボタン（52px）。押したあともボタンにフォーカスを残す |
| 同じ場所 | 出発と同じ場所を到着に選ぶと、2つが入れかわる |

### ② 2つの道をくらべる
| 部品 | 仕様 |
|---|---|
| 結果の文 | 太字1文。「日陰の道にすると、日なたが約○分へります。歩くのは約○分のびます。」差が 0 のときは「ほぼ同じです」 |
| 札（2枚） | 左「日陰の道」（木の絵・緑）、右「近い道」（太陽の絵・オレンジ）。中身: 「日なた ○分」（数字 2.6rem）・「歩く 約○分」・「日陰 ○%」・道の帯・「○m のうち 日なた ○m」 |
| 札の状態 | 地図に出している札は地の色と太い枠、「● 地図に表示中」。出していない札は「押すと地図に出ます」。`aria-pressed` で読み上げにも伝える |
| 同じ道 | 札は1枚「日陰の道＝近い道」。文は「この2か所は、いちばん近い道がそのまま日陰の道です。」 |
| 道の帯 | 日陰＝水色の無地、日なた＝オレンジのしま模様。続く同じ種類はまとめ、幅は距離に比例 |
| 凡例 | 帯の下に「日陰（地下・屋根）」「日なた（地上）」 |
| 320px 未満 | 札を縦に並べる |

### ③ 絵地図で見る
| 部品 | 仕様 |
|---|---|
| 説明 | 「西口 → 区役所・日陰の道。位置と形は目安です。」 |
| 地図 | SVG（400×304）。地: 白に近い水色、公園（中央公園・新宿御苑）は薄緑と木、線路は灰色の帯、大通りは白い太線、地区名（西新宿・歌舞伎町・新宿御苑・JR線） |
| 道 | すべての区間を細い点線（日陰＝水色の破線、日なた＝薄いオレンジの点）。選んだ道は白い縁取りの太線（日陰＝水色、日なた＝オレンジ＋区間の真ん中に太陽の印）。もう1つの道は灰色の点線 |
| 印 | 選べる5か所は絵（都庁・駅・区役所・地下鉄）と名前。途中の地点は小さな白丸。出発は濃い色の「出」、到着は青の「着」のしずく型 |
| 読み上げ | `role="img"` と、道の中身の文（例「西口から区役所までの日陰の道。屋根の下140m、地下130m、…」） |
| 凡例 | 日陰（地下・屋根）／日なた（地上）／もう1つの道 |

## 5. 保存する内容
端末の localStorage（キー `shade-map.shinjuku.v2`）に `{ from, to, mode }` を保存する。読み込み時に、地点が選べる5か所に入っているか・出発と到着が違うか・mode が `shade` か `shortest` かを検査し、だめなら初期状態にする。前の版は URL の `#` に保存していたため、`#from=..&to=..&mode=..` で開かれたらそれを読み、URL から `#` を消す。
