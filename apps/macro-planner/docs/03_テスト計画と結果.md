### T2 で必ず成り立つこと（2万件）
- 基礎代謝は正。目標カロリーは整数で、「やせたい」以外は 消費 ×（1 + 増減）を丸めた値
- 目標は基礎代謝を下回らない。引き上げるのは「やせたい」で 消費 × 0.8 < 基礎代謝 のときだけ
- 目的の順に やせたい ≦ いまの体重 < ふやしたい。動きが多いほど消費が多い。男性は同じ条件の女性以上
- PFC は 0 以上の整数。炭水化物が足りるときは PFC の kcal 合計が目標と ±2kcal 以内。足りないときは炭水化物 0
- 割合は整数で合計 100、各 0〜100。脂質の割合は設定の % と ±1 以内
- たとえはすべて 0 以上の有限の数。ごはんの杯数 × 234 は目標から 0.25 杯分以内
- 入力の読み取り（1万件、3割は全角）: 範囲内の数は必ず通り、範囲外・文字は必ず注意が出る
- 記録（5千件）: 合計は1件ずつ足した値と一致し、残り + 食べた = 目標

### T3 の項目

## 3. 見つかった不具合と対応

| No | 内容 | 見つけた検査 | 対応 |
|---|---|---|---|
| B1 | （前の版）1文字打つたびに画面全体を描き直し、入力欄から外れる。さらに範囲に丸めるため、身長に「1」と打つと「100」に変わり、170 と打てない | 起動して確認 | 入力欄は1回だけ描き、結果だけ描き直す。範囲外は丸めずに注意を出し、直前の値で計算する |
| B2 | （前の版）外部 AI の API キーを端末に平文で保存していた | コードの確認 | AI 連携を削除。前の版のキー `macro.llm` は読まずに消す |
| B3 | （前の版）文字が 13〜14px と小さい。目標の棒がすべて 100% で意味がない | 起動して確認 | 本文 18px・補足 16px 以上。目標はリングと数字で表示 |
| B4 | （前の版の式）「ほとんど動かない」×「減量」で目標が基礎代謝を下回る（1.2 × 0.8 = 0.96） | T2 の設計 | 目標の下限を基礎代謝にし、引き上げたことを表示 |
| B5 | （前の版の式）たんぱく質 2.0g/kg の初期値では、一般の人で国の目安（20%）を超えやすい | 計算の確認 | 初期値を 1.5g/kg にし、国の目安から外れたら知らせる |
| B6 | 公開版で、記録の棒が伸びない（CSP が style 属性を禁じていた） | T10（公開版のコンソール） | 幅を CSSOM（`el.style.width`）で入れる。T3 に「棒が伸びる」「コンソールのエラーなし」を追加 |
| B7 | 390px で「元に戻す」付きのお知らせが丸くつぶれる | T10 | お知らせの幅を内容に合わせた |
| B8 | 320px で見出しが「量の／の」と変な位置で折り返す | T10 | 文節ごとに折り返すようにし、狭い画面では見出しと絵を小さく |
| B9 | 320px で記録の行の名前が細く縦に伸びる | T10 | kcal と PFC を名前の下の行に移した |
| B10 | PC で「1日の食事の目安」が2列で窮屈 | T10 | PC は1列に |
| B11 | 全角で入れた身長が「１５８」のまま残る | T10 | 欄を離れると半角に整える |
| B12 | 前の版からの引き継ぎで、新しい形を保存する前に前の版の体の情報と記録を消していた。保存に失敗すると次に開いたとき記録が失われる（重大度: 高） | 外部レビュー（Codex） | 新しい形で保存できたときだけ前の版を消す。失敗したら引き継いだ内容をメモリ上で使い、次回また引き継ぐ。API キーの `macro.llm` は常に消す。T1 に3件追加（保存成功・保存失敗・前の版なし） |

## 5. 利用者テストの手順（T9）
1. 相手に画面を渡し、「自分の1日の目標カロリーを出して、ごはん何杯分か教えてください」とだけ伝える。
2. 画面を渡してから答えるまでの秒数を測る。説明や手助けはしない。
3. 終わったら「迷ったところ」「分かりにくい言葉」を聞いて書き留める。
4. 合格は **3人とも 60 秒以内**（要件 AC-01）。
