# 理不尽ミニゲーム集 企画設計

## 一文

> ちゃんと遊んで、ちゃんと勝った直後に、ゲーム側の後出しで全部を台無しにされる短編ミニゲーム集。

プレイヤーに技術不足を感じさせるのではなく、ゲーム側が明らかに悪い状態を笑う。感想の目標は「下手だった」ではなく「知らんわ」「ふざけんなw」。

## タイトル候補

- クリアしたのに。
- 知らんがなゲームス
- 後出しゲームセンター
- 台無しゲームズ
- 勝ったと思った？

仮称は **「知らんがなゲームス」** とする。「クリアしたのに。」では、冷蔵庫や意味不明魔法のようにクリア後の失格を使わないゲームを包みにくいため。各収録作は真面目な個別タイトルを持ち、結果画面でコレクション名を見せる。

## 共通フォーマット

1. **一文ルール** — 10語程度。普通のゲームに見せる
2. **本編** — 10〜30秒。実際に操作し、自然に失敗する可能性もある
3. **成功** — CLEAR、1位、撃破などを0.8〜1.5秒しっかり祝う
4. **後出し** — 失格、不可避攻撃、ジャンル転換、意味不明判定
5. **結果** — 3〜6秒。説明しすぎず、絵と間で笑わせる
6. **共有** — 同じゲーム、同じ後出しを友達へ直接送る

一周15〜45秒。失敗時は即再挑戦できるが、後出しを見た後の再挑戦は要求しない。

## 裏切りの種類

同じ「失格」を連続させない。

| 種類 | プレイヤーの期待 | 後出し |
|---|---|---|
| 勝利無効化 | 勝った | 審判、規則、検査で無効 |
| 不可避追撃 | 敵を倒した | CLEAR後に操作不能で攻撃される |
| ジャンル転換 | レースを終えた | 恋愛シミュレーションが始まる |
| ルール再解釈 | 意味を推測した | 言葉と効果が全く対応しない |
| 根拠なし判定 | 観察して答える | 正解に論理的根拠がない |
| 主客逆転 | 助けた | 助けられた側から採点される |
| UI裏切り | ボタンを押す | 結果画面だけ別の意味に変わる |

## 収録候補

### 1. ヒエヒエ冷蔵庫

- 種類：根拠なし判定
- 本編：甘い物だらけの冷蔵庫を見て、説明なしの4キャラから持ち主を選ぶ
- 後出し：正解に根拠はない
- 結果：「いや知らんわ！」
- 共有：正解、自分、送信者の選択を比較する
- 実装負荷：低

### 2. ぜったい殺しにくるシューティング

- 種類：不可避追撃
- 本編：左右移動とショットだけで小型ボスを倒す
- 成功：ボス爆発、操作停止、CLEAR表示
- 後出し：爆煙から一発だけ、非常にゆっくりした追尾弾が出る。CLEAR中で操作できず必ず当たる
- 結果：CLEARの文字が一文字ずつ落ちる
- 注意：本編を長くしない。不可避弾でライフや記録を失わせない
- 実装負荷：中

### 3. 世界一うさんくさい重量挙げ

- 種類：勝利無効化
- 本編：制限時間内にボタン連打。ゲージを満たすと世界記録
- 成功：表彰、紙吹雪、国歌の冒頭
- 後出し：審判が無言で赤旗を三本上げる
- 失格理由候補：ドーピング、重りが発泡スチロール、靴下の長さ違反、審判が記録を見ていなかった
- 結果：「記録 0kg」
- 実装負荷：低

一つの理由を固定せず、友達へ共有するseedで理由を揃える。

### 4. 恋する最終コーナー

- 種類：ジャンル転換
- 本編：文章と簡単な車絵による選択式レース
- 選択：「加速する」「減速して曲がる」「ドリフトする」
- 3〜4回の選択で1位を狙う。物理レースは実装しない
- 成功：表彰台へ移動
- 後出し：ライバルがヘルメットを取り、恋愛シミュレーションの選択肢が出る
- 選択：「ずっと追いかけていた」「まず表彰式を」「車の方が好き」
- 結果：レース成績ではなく好感度が保存される
- 実装負荷：低〜中

恋愛パートは一選択だけで終え、別ゲームを丸ごと始めない。

### 5. 魔王戦だけRPG

- 種類：ルール再解釈
- 本編：魔王との最終戦から始まる。攻撃、回復、魔法がある
- 魔法名：「ギュン」「北北西」「社会保険」「一旦持ち帰る」
- 効果は名前から推測できず、使うまで分からない
- 例：「社会保険」→ パーティ全員の自己負担が3割になる
- 例：「一旦持ち帰る」→ 魔王が検討のため帰宅し、勝利扱い
- 結果：勇者ではなく担当者として表彰される
- 実装負荷：低

## 追加候補

- 釣り：伝説の魚を釣ると、魚から釣り人のマナーを採点される
- クイズ：全問正解後、「出題者の気持ち」を外して0点
- リズム：フルコンボ後、演奏した曲が別の曲だったと判明
- PK戦：決めた後、ゴールが移動していたとVAR判定
- 料理：完璧に作った後、注文が別の客のものだった
- 迷路：出口へ着くと「入口はこちら」と表示される
- 育成：大事に育てた生物が卒業してプレイヤーを置いていく

## 笑いの品質基準

- プレイヤーは本当に一度成功したと感じる
- 後出し前に最低0.8秒は成功を祝う
- 本編の努力は30秒以内。長時間の努力を無効化しない
- 後出しは予測不能でも、見た瞬間に意味は理解できる
- 同じ失格、死亡、夢オチを連続させない
- 人種、性別、体型、障害、病気そのものを失敗理由にしない
- 強い点滅、大音量、写実的な流血を使わない
- ゲームの不親切を、読みにくいUIや操作不能バグで代用しない
- 正解・不正解より、友達へ送った時の会話を成功指標にする

## 共通シェル

各ゲームを独立実装しつつ、以下を共有する。

- ゲームID、round seed、送信者結果を扱うURL fragment
- タイトル、短いルール、スタートカウント
- 成功演出と後出し演出の状態機械
- Web Share APIとリンクコピー
- 送信者/受信者の結果比較
- ミュート、減速モーション、リトライ
- 壊れた共有URLからの安全な復帰

ゲーム本体は共通シェルへ `start → playing → apparentWin → betrayal → result` の状態を返す。

## 実装順

### 縦切り1：ヒエヒエ冷蔵庫

既存アプリを使い、専用グラフィック、4択、理不尽な正解発表、共有比較までを完成させる。共有されるかを確認する。

### 縦切り2：重量挙げ

同じ共通シェルで、連打という実操作と勝利無効化を追加する。冷蔵庫と異なる笑いが成立するか確認する。

### 縦切り3：魔王戦だけRPG

選択式のゲームとルール再解釈を追加する。

この3本が面白くなければ、シューティングやレースへ実装コストをかけない。

## 検証

各ゲームについて5人程度へ次だけ聞く。

- ルールはすぐ分かったか
- 成功したと思った瞬間があったか
- 後出しで笑ったか、ただ腹が立ったか
- 誰か一人へ送りたいか
- 3本のうち、どれを人へ説明したいか

DAUや継続率より先に、共有ボタンを押した人数と、口頭でオチを説明したくなったかを見る。
