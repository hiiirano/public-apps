### T2 で必ず成り立つこと
- 選んだアレルゲンを含む疑いのある料理は、主菜・副菜・汁物のどれにも出ない
- 苦手な言葉に当たる料理（材料で判定、材料に無い言葉は料理名で判定）は出ない
- 「20分以内」なら、すべての料理が20分以内
- 主菜の候補があれば必ず7日分。候補がなければ空で、理由を表示する
- 主菜の候補が7品以上なら、週で主菜が重ならない（「この日を変える」の後も）
- 副菜の候補が7品以上なら毎日副菜がある。汁物を付けない設定なら汁物はない。付ける設定で候補があれば、汁のある麺の日以外は汁物がある
- 買い物リストの量はすべて正、同じ材料・単位は1行、卵などの「個」は整数、100g 以上は 10g 単位
- 残り物の報告（何曜日の何で使ったか）が、実際の献立と一致する
- 作る食事: 選んだ食事だけが出る。選んだら候補がある限り毎日出る。朝は主食＋おかず、昼は1品（＋汁物。汁物 OFF なら1品）。候補が7品以上なら週で朝の主食・昼の1品が重ならない
- 同じ日に同じ料理が2回出ない（「変える」の後も）
- ジャンル: おまかせは 3・2・2 日、「多め」は 4 日＋ほかの2ジャンルも1日以上、同じジャンルが3日続かない（各200通り）
- 残り物: 料理データにある材料（122種）を1つ残り物に入れると、条件で外れていない限り必ず1回以上使う

## 3. 見つかった不具合と対応

| No | 内容 | 見つけた検査 | 対応 |
|---|---|---|---|
| B1 | 「牛肉」と入れても「牛こま切れ肉」の料理が出る（材料名に「牛肉」という文字が無いため部分一致しない） | 利用者の指摘 | 分類タグと言い換え辞書で材料名にそろえて判定（`foods.ts`）。T1・T2・T4 で再発防止 |
| B2 | 「ネギ」で「長ねぎ」が外れない（カタカナとひらがなの違い）。逆に「ねぎ」で部分一致すると玉ねぎまで外れる | 利用者の指摘 | 表記をそろえ（NFKC・カタカナ→ひらがな）、ねぎ類と玉ねぎを別の分類にした |
| B3 | 冷蔵庫の残り（キャベツ・リンゴ・ネギ）が献立に反映されない。使ったかどうかも分からない | 利用者の指摘 | B1 と同じ辞書で照合。まだ使っていない残り物を使う料理を強く優先。何曜日で使うか、使えない理由を表示 |
| B4 | 「和」を選ぶと7日すべて和食 | 利用者の指摘 | ジャンルは「多め」（7日のうち4日）にし、説明を画面に出した |
| B5 | 1日に主菜1品（副菜は小さく、汁物なし） | 利用者の指摘 | 主菜＋副菜＋汁物に。和の汁物が1品しかなかったため汁物を8品追加 |
| B6 | 主菜の候補がちょうど7品のとき「この日を変える」でほかの日と同じ主菜になる | T2 | ほかの日と重なるなら変えずに「ほかに合う料理がありませんでした」と出す |
| B7 | アレルギーのチップの押せる範囲が 41px | T5 | 高さを 48px に |
| B8 | スイッチ（52×32px）と買い物のチェック（24px）が 44px 未満 | T5 | 行全体を押せる大きさにし、見た目は別の部品で描く |
| B9 | 「この日を変える」の読み上げ名と見た目の文字が違う（WCAG 2.5.3） | T6 | 見た目の文字を名前に含める形にした |
| B10 | 閉じた日の札が、隣の開いた札と同じ高さに伸びて空白ができる | T10 | 札の並びを上ぞろえに |
| B11 | 買う量が「187.5g」「卵 11.5個」と細かい | T10 | 足りなくならないよう切り上げて切りのよい数に（T2 で検査） |
| B12 | とんかつにえびの絵、なますに鍋の絵が出る | T10 | 絵の割り当ての順を見直した |
| B13 | 残り物のキャベツを5日も使い、残り物以上に買うことになる | T10 | 1回使えたら優先をやめる |
| B14 | スマホで条件を見ているとき「献立を見る」の帯が出ないことがある | T10 | スクロールのたびに献立の位置で判定する |
| B15 | お知らせが入力欄の上に重なる | T10 | お知らせを画面上に出す |
| B16 | 前の版の保存を引き継ぐとき、新しい形で保存する前に古いキーを消していた。保存に失敗すると（容量不足など）、次に開いたときアレルギーの設定が消える | 外部レビュー（Codex、重要度「高」） | 新しい形で保存できたときだけ古いキーを消す。失敗したら古いキーを残し、引き継いだ内容で動かす。T1 に「保存が失敗する場合」のテストを4件追加 |
| B17 | 汁物の候補が1品しかないとき、朝・昼・晩で同じ日に同じ汁物が出る | T2 | 同じ日に出した料理は、ほかに候補が無ければ付けない |
| B18 | 「変える」を2回押すと元の料理に戻ることがある | T1 | 押すたびに、まだ出していないものにする（一巡したら最初から） |
| B19 | 朝食を「変える」と、その日の昼食まで変わる（昼食が朝食を見て選ばれていたため） | T4 | 朝・昼・晩を先にすべて決めてから「変える」を当てる。ほかの食事は固定 |

| B21 | 1.0 で保存した条件に「作る食事」が無く、そのまま読むと形の検査で初期状態になり、アレルギーの設定が消える | T1（設計時に確認） | 無ければ「晩だけ」として読み、ほかの設定を保つ。テストで確認 |
| B22 | 材料とアレルギーを開くと、横の「変える」ボタンに押されて幅が狭くなり読みにくい | T10 | 開いたときは幅いっぱいにし、ボタンを上に移す |
| B23 | 朝のスープが「おかず」と表示される | T10 | 汁物は「汁物」と表示 |
| B24 | カレーうどんにカレーライスの絵、塩焼きそばにどんぶりの絵 | T10 | 絵の割り当てを見直し、朝昼用の絵を13点追加 |

## 5. 利用者テストの手順（T10）
1. 相手に画面を渡し、「大人2人・子ども1人。子どもは卵アレルギー、夫は牛肉とネギが苦手。冷蔵庫にキャベツがある。和食多めで1週間の夕食を決めて、買い物リストを LINE に送れるようにコピーしてください」とだけ伝える。
2. 画面を渡してからコピーのお知らせが出るまでの秒数を測る。説明や手助けはしない。
3. 終わったら「迷ったところ」「楽しかったか」を聞いて書き留める。
4. 合格は **3人とも 90 秒以内**（要件 AC-01）。
