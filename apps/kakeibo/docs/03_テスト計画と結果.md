### T1 の主な境界
| 境界 | 確かめたこと |
|---|---|
| 月初（1日目） | 3,000円 → 見込み 93,000円（×31）、「ぶれます」の印 |
| 月末（最終日） | 見込み＝合計。残り1日。こえていれば1日あたり 0円 |
| うるう年 | 2024年2月は29日（2,900円 ÷ 10日 × 29 = 8,410円）、2026年2月は28日、2000年は29日・2100年は28日。2024-02-29 が最終日 |
| 支出0 | 見込み0・「収まる」・1日あたり＝予算 ÷ 残り日数 |
| 大きな額 | 1件 99,999,999円 × 住まいと食費でも整数のまま（見込み 3,199,999,968円） |
| 住まい・先の日付 | のばさずそのまま足す。先の日付は累計の線に出さない |
| 過去・先の月 | 過去は見込み＝合計、先の月は書いた分だけ。ほかの月の記録は数えない |
| 予算 | 0・null は予算なし。ちょうど予算は「ぎりぎり」、1円こえると「こえた」 |
| 保存の検査 | 重複 id・実在しない日（2月30日）・0円・小数・知らない費目・危ない id・上限超え・長すぎるメモは、その件だけのぞく |
| 件数の上限 | 20,000 件で書けない・1件手前は書ける・読み込みは上限まで・保存済みの上限超えは捨てない |
| 前の版の引き継ぎ | 保存に失敗しても帳面を返し前の版を残す・成功したら移して消す・読めない環境 |
| 読み込み | よその CSV（2026/10/3、"1,200"、知らない費目）、前の版の JSON / CSV、見出しなし・空・壊れた JSON はエラー |

### T2 で必ず成り立つこと
- 合計＝その月の記録の合計（ほかの月をまぜても）。のばさない分＋のばす分＝合計
- 見込みは整数で、合計を下回らない。最終日は見込み＝合計
- 累計は今日まで値があり減らない。今日の累計＝今日までの記録の合計。今日より先は空
- 残り日数＝月の日数 − 今日 ＋ 1
- 判定は「こえた ＞ こえそう ＞ ぎりぎり（9割）＞ 収まる」の定義どおり。1日あたり × 残り日数 ≦ 残りの予算
- 今日までの記録を1件足すと、見込みは減らない
- 図の点はすべて枠の中。図の上限は見込みと予算より上
- 書き出し（CSV・JSON）→ 読み込みで、id・日付・金額・費目・メモがすべて同じ（カンマ・"・改行・絵文字・= で始まるメモを含む）

## 3. 見つかった不具合と対応

### 前の版（v0.1）を触って見つけた問題
| No | 内容 | 対応 |
|---|---|---|
| P1 | 見た目が割り勘アプリと同じ（クリーム地・太い線・丸い書体） | 紙のノートの見た目に作り直した |
| P2 | AI 連携のために API キーを入れる欄があり、端末に保存していた | 削除。前の版で保存したキーも消す |
| P3 | 入力が 日付→金額→分類（選択肢）→メモ→記録 と長い。分類が「必需・娯楽…」で分かりにくい | 金額→絵つきの費目→書きこむ の3手に |
| P4 | 「このペースだと月末いくら」が文と細い棒だけで、一目で分からない | 大きな金額・判定の札・図に |
| P5 | 家賃を1日に書くと ×30 されて大きく外れる | 住まいはのばさない |
| P6 | 月の切り替えが英語表記の月の欄（端末による） | ‹ › の1か所に |
| P7 | JSON の取り込みで記録が全部置き換わる（消える）。CSV は表示中の月だけで読み込めない | 足す方式に。CSV も全部書き出し・読み込み可 |
| P8 | 全部消すがブラウザの確認窓、取り込みの結果が警告窓 | 画面内の確認と、元に戻す付きのお知らせに |
| P9 | 保存の検査が弱い（実在しない日付・小数・巨大な数が通る） | 形と範囲を検査 |

### 作り直しの中で見つけた不具合
| No | 内容 | 見つけた検査 | 対応 |
|---|---|---|---|
| B1 | 390px で予算の欄が横にはみ出す（442px） | T10・はみ出し調査 | 設定の列を `minmax(0, 1fr)` に |
| B2 | 記録の朱の余白線が、見出しや費目の絵の上を通る | T10 | 記録の札の左の余白を広げた |
| B3 | 予算欄に入ると数字を整え直すため、上書き入力で「200050000」のように前の数字が残る | T3 | 入ったときの整え直しをやめた（カンマ付きのまま読める） |
| B4 | 320px で記録の費目名が縦1文字ずつに折れる | T10 | 狭い画面では絵と余白線を省き、費目名を折らない |
| B5 | 320px で「予算・使った・残り」の数字が折れる | T10 | 狭い画面では字を小さく |
| B6 | 横棒の幅を style 属性で入れており、公開版の CSP で消える | 作りの見直し | CSSOM で入れるように |
| B7 | スマホで下へ送ると、書きこむ欄まで戻るのが遠い | T10 | 書きこむ欄が見えないときだけ下に「書きこむ」帯 |
| B8 | 画面検査が、閉じた「日付・メモ」の中の欄を重なりとして数える | T4 | 検査側で閉じた中身を対象外に（画面の不具合ではない） |
| B9 | 記録が 20,000 件をこえても書けたが、次に開くと読み込みで先頭 20,000 件だけ残り、書いた記録が消える | Codex レビュー（中） | 書く・読み込むときに上限を当てて知らせる（「記録は20,000件までです…」「上限で入らない ○件」）。保存済みの上限超えは捨てずに読む。単体テスト 4 件 |
| B10 | 前の版のデータを読めても、新しいキーへの保存に失敗（容量不足など）すると空の帳面で開く | Codex レビュー（中） | 保存の失敗を読み込みと分け、引き継いだ帳面をそのまま返す。保存できなかったときは前の版のデータを消さずに残す。単体テスト 5 件 |

## 5. 利用者テストの手順（T9）
1. 相手に画面を渡し、「今、外食で1,200円使いました。書いてください」とだけ伝え、書き終わるまでの秒数を測る（合格 10 秒以内、AC-01）。
