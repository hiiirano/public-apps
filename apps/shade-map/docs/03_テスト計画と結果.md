### T2 で必ず成り立つこと
- 道は必ず出発地から始まり目的地で終わり、1区間ずつ途切れずにつながる（区間の両端・線の向き・案内文の向きも合う）。同じ地点を2回通らない
- 近い道は距離、日陰の道は「日陰＋日なた×5」が、総当たり（フロイド–ワーシャル法）で求めた最小値と一致する
- 日陰＋日なた＝全体の距離。日陰の割合は 0〜100 の整数で、100% になるのは日なたが 0m のときだけ
- 日なたの分 ≦ 歩く分。0 分になるのは 0m のときだけ
- 日陰の道は近い道より短くならず、日なたは近い道より多くならない
- 逆向きでも近い道の距離は同じ。同じ入力には同じ答え
- つながっていない2点は「道がない」エラーになる（落ちない）
- どんなに壊れた保存内容でも、選べる地点・違う2点・正しいモードの形で返る

## 3. 見つかった不具合と対応

| No | 内容 | 見つけた検査 | 対応 |
|---|---|---|---|
| B1 | 公開版で、道の帯の幅が距離に比例しない（日陰 660m と日なた 50m が同じ幅）。CSP が `style` 属性を禁じていたため | T10（320px の画面） | 幅を JavaScript から設定するようにし、T3 に幅の検査とコンソールのエラー（CSP 違反）の検査を足した |
| B2 | 選ぶ欄の名前が「出出発」と読まれる（丸印の文字が名前に入る） | T3 | 丸印をラベルの外に出した |
| B3 | 開いたまま前の版の URL（#from=..）を入れても反映されない | T3 | `hashchange` でも読むようにした |
| B4 | ダークで「出」の丸印と地図の出発の印が背景に溶ける | T10 | 文字色と地の色をテーマに合わせた |
| B5 | 到着の印が地図の「歌舞伎町」の文字に重なる | T10 | 地区名の位置を動かした |
| B6 | PC で絵地図の下が大きく空く | T10 | 並びを「選ぶ・くらべる｜地図」「歩き方｜データについて」に変更 |
| B7 | 320px で根拠の表が横にはみ出し、行が縦に長い | T10 | 表をやめ、区間ごとの札の並びにした |
| B8 | 「目安です」の帯・説明文が 15.6px で、本文 16px の基準に足りない | T4 | 0.95rem（16.15px）に上げた |
| B9 | 道の帯で、同じ日陰の区間の間に白い切れ目が入り、区間が多く見える | T10 | 続く同じ種類の区間をまとめた |

前の版から引き継いだ指摘（2026-10-20 のレビュー）: 公開 URL の 404 は配信側の問題のため取りまとめ役が確認する。「日陰」という題と中身の差は、「目安です」の帯と「データについて」で限界を書いて対応した。外歩きの文字が小さい点は、「日なた ○分」を札でいちばん大きく出して対応した。

## 5. 利用者テストの手順（T9）
1. 相手に画面を渡し、「新宿駅の西口から区役所に行きます。日陰の道にすると、日なたを歩く時間は何分へりますか？ 歩く時間は何分のびますか？」とだけ伝える。
2. 画面を渡してから答えるまでの秒数を測る。説明や手助けはしない。
3. 続けて「このアプリの答えはどのくらい正確だと思いますか？」と聞き、「目安」「季節・時刻は考えていない」が伝わっているかを書き留める。
4. 合格は **3人とも 20 秒以内に正しく答える**（要件 AC-01）。
